用户否决了"切换 Riot 官方 API"的建议，项目数据源锁定为 **OP.GG 玩家页**。因此本文件不再把 OP.GG 列为"不可用"，而是：

- 技术层：直接重放页面自身的 `getGames` Server Action，用游标翻页覆盖完整窗口，无需浏览器；

## 3. 方案选型

选定 **纯 HTTP Server Action 采集**（详见 `opgg-collector-design.md` V2）：

1. **主路径**：GET 页面 HTML → 提取 `puuid` 与动作 ID → POST `getGames` → 以 `endedAt` 游标翻页，直到覆盖统计窗口。
2. **动作 ID 发现**：从页面 chunk 中匹配 `createServerReference("<id>","getGames")`，按构建号缓存；支持环境变量手工固定。
3. **回退路径**：动作不可用时解析 JSON-LD（约 10 场），并标记 `collector=jsonld` 与完整性告警。
4. **不使用 Playwright**：无需浏览器、无需 DOM 解析，CI 成本与请求量更低。
5. **不采用**：复刻其它页面内部接口；仅使用这一个已验证的动作。

## 4. 场次覆盖与完整性策略

- `getGames` 每页 20 场，游标为上一批最老一场的 `created_at`，实测批间**零重叠**，可一直翻到账号历史尽头。
- 单日战报通常 1~3 页即可覆盖（样例账号 20 场覆盖 4 天）。
- 完整性判定规则（必须写入战报元数据）：
  1. 本批最老一场 `start_time` **早于**窗口开始 → `complete=true`；
  2. 触达 `max_pages` 或时间预算，且仍未覆盖窗口 → `complete=false`，附 `coverage_warning`；
  3. 批次不足 20 场且仍未覆盖 → `complete=true`，说明已到历史尽头。
- 绝不把"列表结束"当作"当天没有更多对局"。

## 5. 合规姿态（风险已接受，但不放弃约束）

用户决策：接受 OP.GG 使用条款风险，继续推进。在此基础上保留以下**硬约束**，避免把风险放大为封禁或法律问题：

1. 请求频率：每账号每日 ≤ 2 次完整采集（1 次 HTML + 通常 1~3 次动作请求）；账号串行、不并发。
2. 不绕过任何访问控制：出现 401/403/429/验证码 → 立即停止并告警，不重试、不换代理、不伪造会话。
3. 不携带个人 Cookie/登录态：只用匿名访问。
4. 输出必须标注"数据来源：OP.GG"及采集时间；不转售、不批量抓取其他账号。
5. 不在 OP.GG 高峰时段（韩国晚间）运行；定时任务安排在上海时间早间。
6. 保留 `source-policy-review.md` 中的条款原文与本次决策记录，作为风险留痕。

## 6. 风险登记与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 动作 ID / flight 结构随构建变更 | `getGames` 调用失败 | 自动发现 + 按构建号缓存 + 环境变量覆盖；失败回退 JSON-LD 并告警 |
| 游标语义变化 | 翻页重叠或漏场 | 每次校验批间 `created_at` 单调递减、`match_id` 零重叠 |
| 被限流/封禁 | 采集中断 | 低频、串行、失败即停；告警后人工介入 |
| 更新延迟 | 早间日报缺前一晚对局 | 上海时间 05:00 运行 + `workflow_dispatch` 手动补跑；战报标注采集时间 |
| 英雄名本地化 | 统计口径漂移 | 固定 `en` locale；使用 `champion.key`（如 `yorick`）作稳定键 |
| 账号改名 | URL 失效 | 配置中保存 Riot ID，采集前校验；失败告警 |
