### 2.2 浏览器首屏与分页（2026-10-21 补充实测）

| 操作 | 对局行数 | 网络请求 |
| --- | --- | --- |
| 冷加载首屏 | 20 | 首屏 SSR 已含 20 场 |
| 点击 "Show more" ×1 | 40 | **1 次 `getGames` POST**（早前"0 次"结论已作废） |
| 再点 "Show more" | 按钮消失，停在 40 | 客户端缓存耗尽，未再请求 |
| 历史会话（多次导航 + 点击） | 曾累积到 80 | 未逐次确认 |
| 展开单局详情 | — | 0 次新请求，计分板已内嵌 |

补充结论：

- `Show more` 会触发 `getGames` Server Action（`next-action: 409a2b9c...`），每次返回更早的 20 场。
- 页面上另有一个周期性刷新动作（`next-action: 40f052...`，响应约 70 字节），不含对局，勿混淆。
- 浏览器内 `window.fetch` 补丁无法捕获 Next.js 内部请求，**不能据此判断"没有请求"**；应以 DevTools 网络面板/服务端直连为准。

### 2.3 分页参数探测

| 探测 | 结果 |
| --- | --- |
| `/games` 子路由 | 404 |
| `?page=2` | 参数无效，返回同一批最近对局 |
| `?game_type=ARAM`、`?game_type=SOLORANKED` | 参数无效，列表未变化 |
| 视图切换（全部/排位/大乱斗/竞技场） | 客户端过滤，非服务端参数 |
| `getGames` 的 `endedAt` 游标 | **有效**，每次 20 场，可连续翻页 |

**结论：URL 上没有分页参数，但 `getGames` 的 `endedAt` 游标可覆盖任意深度。**

### 2.4 `getGames` 纯 HTTP 重放验证（关键）

使用 Python 3.12 `urllib`（无 Cookie、无浏览器）执行：

| 步骤 | 结果 |
| --- | --- |
| GET 页面 HTML | 200，713,003 字节，46 个 JS chunk |
| 动作 ID 发现 | 在 chunk `1534-d4a9d3db31efdd12.js` 中匹配到 `createServerReference("<id>","getGames")` |
| POST `getGames`（首次，`endedAt=""`） | 200，783,826 字节，20 场 |
| 第 1 批时间范围 | `2026-10-20T14:58:42+09:00` ~ `2026-10-17T13:40:03+09:00` |
| 第 2 批（游标=最老 `created_at`） | 20 场，`2026-10-17T13:14:43` ~ `2026-10-14T14:17:22` |
| 批间重叠 | **0** |
| 307 跳转 | `/en/...` → `/lol/summoners/...`，需保留 POST 方法与 body |
| 首场字段 | `game_length=1698`、`champion.key=yorick`、`position=TOP`、`role=FIGHTER`、KDA `6/4/1`、`cs=279` |

**结论：纯 HTTP 可稳定获取完整字段并按游标翻页，无需 Playwright。**

## 8. 关键风险复核

| 风险 | 本次实测 | 结论 |
| --- | --- | --- |
| 内部接口随时变化 | 页面架构已从旧 bypass API 迁移到 Next.js RSC/Server Action | 旧方案（第三方 SDK）已不可用；新版结构同样会随发布变化 |
| 使用许可不明确 | 条款与帮助中心冲突依旧 | 未解决，且是**阻断性**问题 |
| 动态参数或会话要求 | 匿名 GET 无需凭据 | 采集门槛低，反而意味着 ToS 风险更直接 |
| 分页逻辑误判 | 无 URL 分页；只能 JS 点击 | 完整性无法用纯 HTTP 保证 |
| 更新延迟 | 未能实测 | 未知 |
| 某些模式无数据 | 帮助中心确认 | 需在战报中声明 |
| 账号标识变化 | slug 依赖 Riot ID | 改名即失效 |
