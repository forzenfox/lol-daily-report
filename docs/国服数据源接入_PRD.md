# 国服数据源接入 PRD

- 文档版本：V1.0
- 日期：2026-10-30
- 关联调研：[sqgg-feasibility.md](research-output/sqgg-feasibility.md)
- 关联现状：`LOL韩服主播每日战报生成器_PRD.md`（韩服日报，数据源 OP.GG）
- 结论前提：用户已确认接受三项约束——每日仅约 1 小时可查询、脚本登录会踢掉本人设备会话、账号密码托管到 GitHub Actions Secrets

## 1. 背景与目标

### 1.1 背景

当前日报只覆盖韩服主播，数据来自 OP.GG。国服主播同样需要每日战报，但 OP.GG 不覆盖国服，需要接入国服数据源。调研确认 `sqgg.cc` 提供国服全大区战绩查询，但有三条与传统数据源不同的产品约束：

1. 查询权限来自**每日签到**，单次签到只开放约 1 小时的查询窗口；
2. 账号采用**单会话**模型，任一设备登录都会使其它设备（包括自动化脚本）的会话失效；
3. 访问权限与登录会话分离：登录成功不等于可查询，必须处于签到后的有效窗口内。

因此这不是"换一个接口地址"，而是新增一条**受时间窗约束的每日任务链路**，产品必须定义窗口、失败、重试与降级行为，避免在无权限时产出空报告或错误报告。

### 1.2 目标

- 维护者每天 05:00（Asia/Shanghai）无需人工介入，即可得到与韩服日报格式一致的国服日报。
- 在签到成功后的有效窗口内完成全部国服账号采集；窗口外或签到失败时，任务明确失败并且**不产出任何战报文件**。
- 读者看到的国服日报与韩服日报在结构、字段口径、图片版式上保持一致，仅数据来源标注不同。

## 2. 用户与场景

| 角色 | 关注点 | 使用方式 |
| --- | --- | --- |
| 项目维护者（唯一操作者） | 任务是否按日产出、失败是否可见、是否需要人工补跑 | 维护配置与仓库 Secret，查看 Actions 结果与产物 |
| 日报读者（主播粉丝） | 当天战绩是否完整、口径是否可信 | 读取 `output/{日期}/` 下的 Markdown、PNG、JSON |
| 国服主播账号（被查询方） | 数据是否被正确统计 | 由维护者确认已获授权后加入配置 |

典型流程：

```text
05:00 定时触发
  → 读取配置中的国服账号
  → 使用签到账号进入有效窗口
  → 在窗口内逐个采集国服账号当日对局
  → 生成 Markdown / JSON / PNG（与韩服一致）
  → 提交产物分支并创建 PR
```

## 3. 范围

### 3.1 P0（必须实现）

- 账号级数据源选择：同一份配置中可同时存在国服账号与韩服账号。
- 每日签到：任务启动时完成签到或确认当前仍在有效窗口内。
- 国服战绩采集：按上海时区当日窗口采集，只取单双排（5v5 排位）。
- 会话与凭据管理：凭据来自环境变量/仓库 Secret，不在配置与产物中出现。
- 失败、跳过与告警：无权限、无对局、部分采集、账号不存在等结果可区分。
- 产物与来源标注：输出结构与韩服一致，来源标注为国服数据源。

### 3.2 P1（本期实现，但不作为阻塞项）

- 多个国服账号共享同一次签到窗口，串行采集。
- 支持人工触发补跑（在有效窗口内）。
- 采集完整性标记：翻页提前结束、页数上限、请求失败等情况写入告警。

### 3.3 不做

- 不做网页端、管理后台或人工交互界面。
- 不做多签到账号的负载均衡或自动切换。
- 不做超出有效窗口的历史回补：补跑必须在签到后的窗口内完成，窗口结束即无法继续。
- 不改动韩服 OP.GG 链路及其统计口径。

## 4. 产品模型

| 对象 | 定义 | 关键属性 |
| --- | --- | --- |
| 数据源 | 一组账号数据的提供方 | 韩服=OP.GG；国服=SQGG |
| 签到账号 | 拥有 SQGG 查询权限的账号，与主播账号无关 | 邮箱、密码（仅存 Secret） |
| 访问窗口 | 一次有效签到后允许查询的时间区间 | `开始=签到时刻`，`结束=签到时刻+约 1 小时` |
| 主播账号 | 日报统计对象 | 展示名、`名称#标签`、大区、数据源 |
| 采集任务 | 一次日报生成过程 | 日期、窗口、账号列表、结果状态 |
| 产物 | 每个账号三件套 | Markdown、JSON、PNG |

对象关系：一个签到账号可服务多个国服主播账号；一次签到只产生一个访问窗口；一个访问窗口内可执行多次采集，但全部采集都必须在窗口结束前完成。

## 5. 功能需求

### FR-01 账号配置与数据源选择

**目的**：让国服账号与韩服账号在同一套配置中共存，且不改变韩服现有行为。

**规则**

- 每个账号声明数据源；未声明时按韩服（OP.GG）处理，保证旧配置可直接运行。
- 国服账号必须声明所在大区；大区名称使用站点展示的中文名（如"艾欧尼亚"）。
- 账号标识保持 `名称#标签` 形式，与韩服一致。
- 国服账号与韩服账号各自独立启停（`enabled`）。
- 配置中禁止出现邮箱、密码、会话令牌等敏感值。

**结果**：任务按账号逐条处理，单账号失败不影响其它账号。

**异常**

- 国服账号缺少大区：任务启动即失败，提示配置错误，不进入采集。
- 大区名称不存在：该账号失败，错误信息指明"大区不存在"，其它账号继续。

### FR-02 每日签到与访问窗口

**目的**：在每次任务开始时确保处于可查询状态，且不因重复签到或窗口过期浪费时间。

**触发**：每次日报任务启动时，先执行签到判定，再进入采集。

**规则**

- 每日仅能签到一次；签到成功后，访问窗口从签到时刻开始，持续约 1 小时。
- 若当日已签到且当前时间仍在窗口内：直接进入采集，不再尝试签到。
- 若当日已签到但窗口已结束：本次任务判定为"无权限"，当日不可恢复。
- 若当前无有效会话：先用签到账号登录；登录后若检测到今日已签到或仍处于有效窗口，则**不重复签到**，直接进入采集。
- 站点在窗口内不限制查询的时间范围，因此同一任务可以按配置传入的目标日期采集任意历史日期（历史补跑），但窗口本身不会因补跑而延长。
- 同一任务内的多个国服账号共用同一个访问窗口；采集按配置顺序串行执行。

**结果与状态变化**

| 情形 | 任务表现 |
| --- | --- |
| 签到成功 | 记录窗口结束时间，进入采集 |
| 已签到且窗口有效 | 不重复签到，进入采集 |
| 已签到但窗口已过 | 任务失败，不产出任何文件，错误信息为"访问窗口已结束" |
| 登录失败（密码错误/账号锁定） | 任务失败，不产出任何文件 |

**异常**

- 窗口内采集失败：同一请求最多重试 2 次；重试后仍失败且已获得部分对局时，输出并标注"不完整"；一条对局都没有时该账号失败。
- 窗口外的任何失败都不重试，直接失败，避免无效请求。

### FR-03 国服战绩采集

**目的**：在窗口内准确获取当日对局，且与韩服口径一致。

**处理规则**

- 统计窗口沿用上海时区当日 00:00:00 至次日 00:00:00；`目标日期` 可指定为历史日期，用于补跑缺失日报。
- 只统计单双排（5v5 排位）；其它模式不进入统计、明细、称号与任何产物。
- 对局按时间倒序获取，翻页直到最老对局早于目标日窗口起点、或没有更多对局、或达到页数/时间预算。
- 历史日期越久远，需要的翻页次数越多；页数预算由配置控制，预算不足时标记不完整。
- 对局去重以唯一对局标识为准。
- 采集时间不得当作比赛时间；比赛时间以对局开始时间为准。

**结果**

- 有符合条件的对局：生成三件套产物。
- 无符合条件的对局：不创建目录、不产出文件，任务标记为"跳过"，退出码为成功。

**异常与完整性**

- 采集在翻页中途失败：标记"不完整"，仍输出已获得的对局，并在产物中提示数据可能不完整。
- 页数或时间预算触顶：标记"不完整"，提示提前结束原因。
- 响应结构与预期不符：该账号失败，错误信息指明结构变化，便于人工排查。

### FR-04 会话冲突与凭据

**目的**：在单会话模型下明确"谁在用这个签到账号"，降低互相踢下线带来的偶发失败。

**规则**

- 凭据只从环境变量/仓库 Secret 读取，日志与产物中不得出现密码、完整令牌。
- 优先复用已保存的会话；无可用会话时才使用邮箱密码登录，以减少踢下线次数。
- 会话更新（登录或刷新）后，新令牌必须先落盘再发起后续请求；旧令牌立即失效。
- 人工在浏览器登录会让脚本会话失效：下一次任务自动重新登录即可恢复，无需人工处理。

**结果**：维护者本人的浏览器/手机会话可能被踢下线，属已确认的预期行为。

### FR-05 失败、跳过与告警

**目的**：让维护者能一眼区分"今天没打排位"和"今天没权限/出错"。

**规则**

| 结果 | 退出码 | 产物 | 日志 |
| --- | --- | --- | --- |
| 全部账号成功 | 0 | 有 | 每个账号一行成功信息 |
| 有账号无排位对局 | 0（跳过） | 该账号无产物 | 明确标注"当日无 5v5 排位对局" |
| 无访问权限 | 非 0 | 无 | "访问窗口已结束/签到失败" |
| 账号不存在、结构变化、网络失败 | 非 0 | 该账号无产物，其它账号不受影响 | 错误原因 |

**告警**：任务失败时 GitHub Actions 作业失败，由仓库通知机制触达维护者；本期不额外接入第三方告警。

### FR-06 产物与来源标注

**目的**：读者无法区分两个数据源时，日报可信度会下降。

**规则**

- 产物目录、文件命名、Markdown 结构、图片版式与韩服保持一致。
- 来源标注：国服日报标注国服数据源名称，并保留账号原页面链接。
- JSON 中记录数据源标识、采集时间、窗口、页数与完整性标记，供后续核对。
- 国服与韩服账号的产物互不覆盖（按账号展示名命名，沿用现有规则）。

### FR-07 安全与隐私

**规则**

- 密码与会话令牌只存在于 GitHub Actions Secrets 与本地缓存文件（不入库）。
- 缓存文件权限限本人可读写；提交产物时不得包含缓存目录。
- 采集仅限已获主播本人授权、且公开可查的账号。
- 日志脱敏：邮箱只保留前 2 位与域名，令牌只保留长度与前后各 4 位。

## 6. 共享规则

| 规则 | 内容 |
| --- | --- |
| 统计窗口 | Asia/Shanghai 当日 00:00:00（含）至次日 00:00:00（不含） |
| 日报口径 | 仅单双排（5v5 排位），沿用现有韩服口径 |
| 账号隔离 | 单账号失败不阻塞其它账号；图片失败不阻断 Markdown/JSON |
| 窗口共享 | 一次签到窗口服务本次任务内全部国服账号；串行采集 |
| 重试边界 | 仅窗口内重试，最多 2 次；无权限与结构错误不重试 |
| 时间预算 | 单次任务内国服采集总时长不得超过窗口剩余时间，并预留 5 分钟余量 |

## 7. 状态与流转

### 7.1 会话状态

| 状态 | 进入条件 | 允许动作 | 退出条件 |
| --- | --- | --- | --- |
| 无会话 | 无缓存令牌且未登录 | 登录 | 登录成功 → 有效 |
| 有效 | 已登录且窗口未结束 | 签到、采集、刷新 | 窗口结束 → 到期；被顶号 → 失效 |
| 到期 | 当前时间晚于窗口结束 | 仅允许等待次日 | 次日签到 → 有效 |
| 失效 | 令牌被新会话顶掉或非法 | 重新登录 | 登录成功 → 有效 |

### 7.2 任务状态

```text
启动
 ├─ 配置错误 ────────────────────────▶ 失败（不产出）
 ├─ 登录失败 ────────────────────────▶ 失败（不产出）
 ├─ 窗口已结束（今日已签到）──────────▶ 失败（不产出）
 └─ 窗口有效
     ├─ 采集成功且有排位对局 ─────────▶ 成功（产出三件套）
     ├─ 采集成功但无排位对局 ─────────▶ 跳过（不产出文件）
     ├─ 采集部分失败（已有对局）──────▶ 成功但标注不完整（输出已获得部分）
     └─ 采集失败且无任何对局 ──────────▶ 该账号失败；结构变化/账号不存在同样失败
```

## 8. 异常与边界

| 场景 | 产品行为 |
| --- | --- |
| 当日已签到且窗口还有剩余时间 | 不重复签到，直接采集 |
| 当日未签到，签到成功 | 记录窗口结束时间，立即采集 |
| 窗口只剩不足 5 分钟 | 判定无法完成采集，任务失败并提示窗口不足(failure)，避免产出不完整日报 |
| 多个国服账号，第一个采集较慢 | 后续账号按剩余时间预算裁剪页数；不足时标记不完整并告警 |
| 同一账号当日跨 0 点 | 以对局开始时间归属日期，0 点后开的局计入新的一天 |
| 目标日期为历史日期（补跑） | 只要当前处于有效窗口即可补跑；窗口结束后该日无法再补 |
| 历史日期较早，翻页预算不足 | 输出已获取部分并标记不完整，提示调高页数上限 |
| 主播当日只打了非排位 | 跳过，不产出文件 |
| 同一对局被重复返回 | 按唯一对局标识去重 |
| 令牌在窗口内被人工登录顶掉 | 该次采集失败；窗口内可自动重新登录并重试（消耗重试次数） |
| 无网络/超时 | 窗口内重试 2 次；仍失败则该账号失败 |
